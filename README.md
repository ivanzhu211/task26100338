# canvas — 白板协作引擎的画布同步模块

纯进程内存的 Go 库，由上层 WebSocket 网关直接调用，不含网络/接口层。

## 模型

- 每页画面由笔画按受理顺序叠放，后受理的在上层；笔画的作者、颜色、
  透明度、粗细、点序列原样保留（受理时冻结点切片，之后不可变）。
- 三种操作：`OpDraw` 落笔、`OpErase` 擦除指定一笔（不存在则无效果）、
  `OpClear` 清除某参与者在本页此前受理的全部笔画。
- 每页操作按受理顺序从 1 连续编号；每个订阅者按编号顺序收到推送，不漏不重。

## API

```go
e := canvas.NewEngine()
ev := e.Accept(pageID, op)                    // 受理操作，返回编号后的事件
snap, sub := e.Enter(pageID, participant)     // 进入：起点画面 + 订阅
res, sub := e.Resume(pageID, participant, lastSeq) // 断线重连
e.Leave(pageID, sub)                          // 退出（幂等）
```

- `Enter` 返回起点画面及其编号 `BaseSeq`，之后从 `sub.C` 接着收推送，
  二者在同一锁内原子衔接：起点画面 + 后续推送 ≡ 从头重放全部操作。
- `Resume`：断开期间新增操作 ≤ `ReplayLimit`(5000) 条时，`res.Replay`
  只含缺的那一段；否则 `res.Snapshot` 给新的起点画面。
- 订阅者积压超过 `MaxLag`(4096) 条未取即判定卡住：推送通道关闭且
  `sub.Err() == ErrLagged`，上层必须让其重新进入，绝不静默跳号。

## 一致性设计

- 画面状态随受理即时更新；每累计 `MergeThreshold`(5000) 条未合并操作
  推进一次 `baseSeq`（合并进快照）并裁剪日志。已合并的最近 5000 条事件
  仍保留在日志中供断线补发，因此日志长度有界（≤ 约 1 万条）。
- 擦除/清除直接作用于画面状态，对已并入快照的笔画照样生效。
- 每页一把锁，页间互不阻塞；受理热路径只做状态应用 + 日志追加 +
  非阻塞扇出，卡住的订阅者、进入/重连风暴、快照合并不影响同页与其他页。
- 进入/重连只拷贝当前可见笔画切片头（≤ 可见笔画数），耗时与累计操作数无关。
- 内存有界：日志 ≤ 约 1 万条事件，每订阅者缓冲 ≤ 4096 条。

## 测试

```sh
go test ./...        # 全部
go test -race ./...  # 含竞态检测
```

- `canvas_test.go`：三种操作语义、清除只影响此前笔画、起点画面+推送
  ≡ 从头重放、编号连续、笔画数据原样保留、卡住重置、退出幂等、页间隔离。
- `reconnect_test.go`：缺口恰好 5000 条只补发、5001 条给新起点；
  合并后补发段仍可用；合并后擦除/清除仍生效；10 万条操作后进入/重连耗时不增。
- `stress_test.go`：多页多人并发落笔/擦除/清除（每页 1.2 万条，合并多次），
  期间不断进入/重连/长期不取推送；最终每人画面与从头重放完全一致。
- `latency_test.go`：卡住订阅者 + 进入/重连风暴 + 合并进行中，
  落笔受理 p99 ≤ 10ms（实测约 0.9ms）。
